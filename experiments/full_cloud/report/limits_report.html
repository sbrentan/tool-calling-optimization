📊 Section 1: MCP (Baseline) - Scaling Limits

The Model Context Protocol (MCP) approach passes all available tools to the LLM in a single call. While this achieves high accuracy with small tool sets, it fails to scale due to context window limitations.

Key Limitations:
  • Context Window Token count grows linearly with tool count
  • Practical Limit Cannot reliably test with ≥500 tools
  • Cost High token usage = higher API costs

MCP accuracy degradation as tool count increases. Red markers indicate experiments with high error rates.

Token usage scales linearly with tool count, quickly exceeding context limits.

📊 Section 2: Clustering - Hierarchical Selection

Clustering introduces a two-step hierarchical approach: first select a category, then select a tool within that category. This enables scaling to large tool sets but introduces category selection errors.

Trade-offs:
  • Scalability Can handle 500+ tools with manageable context
  • Accuracy Loss Category selection errors cascade to tool selection
  • Backtracking Allows recovery from wrong category selection at cost of more steps

📊 Section 3: Hybrid - RAG-Enhanced Category Selection

The Hybrid methodology uses RAG to retrieve relevant categories instead of presenting all categories to the LLM. This improves category selection accuracy while maintaining the ability to scale.

Improvements:
  • Better Category Selection RAG filters to most relevant categories
  • Token Trade-off More tokens than pure clustering, less than MCP
  • Scales to 500-985 tools Successfully tested at large scale

📊 Section 4: RAG - Direct Tool Retrieval

RAG bypasses category selection entirely, using vector similarity to retrieve the most relevant tools directly. This provides high accuracy with constant token usage regardless of total tool count.

Key Advantages:
  • No Category Errors Direct tool retrieval eliminates category selection failures
  • Constant Context Fixed K tools = predictable token usage
  • High Accuracy Often matches or exceeds MCP baseline

Retrieval Recall Analysis

Retrieval recall measures whether the correct tool was present in the retrieved candidate set. High retrieval recall with lower final accuracy indicates the LLM is struggling with selection from candidates; low retrieval recall indicates the embedding-based retrieval is the bottleneck.

📊 Section 5: Adaptive RAG - Dynamic K Selection

Adaptive RAG extends RAG by dynamically selecting K based on similarity score patterns. When a query clearly matches one tool, fewer tools are retrieved; when ambiguous, more are retrieved.

Optimization:
  • Context Efficiency Reduces tokens when fewer tools are needed
  • Maintained Accuracy Dynamic K doesn't sacrifice accuracy
  • Complexity Requires tuning of similarity thresholds

🔍 Key Takeaways

  • MCP works well for small tool sets (<200) but doesn't scale
  • Clustering enables scale but loses accuracy due to category selection errors
  • Hybrid improves on clustering by using RAG for category selection
  • RAG provides the best balance: high accuracy with constant token usage
  • Adaptive RAG optimizes RAG further by dynamically adjusting context size
